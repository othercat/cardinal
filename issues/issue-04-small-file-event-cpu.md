# #4 频繁小文件写入时的 CPU 占用

r6（0.1.28）在已交付的 r5 工作区上实现，原构建基线为 `0460a4d3c7564b8130ee8ba33e0fe7875f6912e0`，集成分支为 `master`。[总管 #1](issue-01-overall-management.md) · [GitHub Issue #4](https://github.com/othercat/cardinal/issues/4)

## 可见行为

- 本机与移动卷用相同的规则处理实际 FSEvents 通知。仅对已知小于 4,096 字节的冷门格式普通文件延后属性读取。同一路径在固定 1 秒内反复写入只读取一次最终状态。达到 4,096 个不同的待处理路径时提前处理，以限制内存。核对后发现文件长大，后续按新大小处理。
- 常用格式复用现有的文档、归档、源码、图片、音视频等扩展名集合，含大小写混合的 TXT、ZIP、MD、MID、MIDI。大小未知、大小达到 4 KiB、目录、符号链接、需要核对的硬链接，以及创建、删除、改名和丢失事件的处理均保留快路径。
- 「事件」保留最近 10,000 条实际通知，文件结果只在受影响的路径已完成核对后更新。搜索拆分大小写敏感的宽目录路径时会利用名称索引缩短按路径查找。可见文件保留 Finder 图标，变动文件的预览缩略图、外观或复用的行 ID 会按需重新提取。
- 等待处理的事件会阻止持久化游标越过它们。正常退出时可完成待处理的一批，中途快照保留可重放的位置。移动卷持续写入时每 5 分钟保存整卷快照，退出或弹出时保存已处理的变更。回归中还修复了弹出时卷根的重扫通知可能跳过最后写盘的问题。

- HFS+ 与 APFS 映像的插拔、热写后离线重启、同名卷隔离和恢复搜索连续通过 3 次。已显示为 997 字节的小文件，弹出后完全重开仍从本机缓存读回 997 字节。

## 实机测量方法

测试使用隔离 bundle ID 的生产模式 Tauri / WKWebView 窗口和独立快照，在 APFS 临时目录预置 20,000 个静态文件，使用另一个进程反复覆写已存在的文件。写入者单独计量。CPU 用进程实际累计的用户态与内核态时间除以测量窗口，单核满载为 100%。应用原生进程与专属 WebKit 进程分别计量。延迟从写入完成至匹配行在 DOM 显示新值，包含索引、IPC 和渲染。

下表为 3 组交替对照的中位数，采样时没有其他编译作业。整组包含应用原生进程与该窗口的 WebContent、GPU 和 Networking。持续负载为重复写 128 个已存在的文件，每秒 2,560 次，每轮 8 秒。

| 场景 | r5 整组 CPU | r6 整组 CPU |
| --- | ---: | ---: |
| 窗口可见，空闲 | 5.48% | 4.83% |
| 窗口可见，持续写不足 4 KiB 的 `.tmp` | 136.55% | 8.21% |
| 窗口可见，同样写入常用格式 | 126.84% | 53.81% |
| 窗口可见，持续写 4,096 / 8,192 字节的 `.tmp` | 125.24% | 47.43% |
| 窗口隐藏，空闲 | 0.29% | 0.47% |
| 窗口隐藏，持续写不足 4 KiB 的 `.tmp` | 17.74% | 3.00% |

小 `.tmp` 前台压力下原生进程从 88.92% 降至 2.22%，WebContent 从 37.88% 降至 4.35%。写入结束后再计入 3.25 秒，整组平均占用的中位数仍从 99.35% 降至 7.80%。普通探针的 r6 可见延迟中位数为 53–60 ms，704 字节的冷门探针为 1,072 ms。与小文件压力同时发生时，常用格式单次实测为 55–78 ms，中文小文件创建、改名、删除为 51、55、92 ms。

用同一文件往返跨过大小边界时，704 → 4,096 字节在 1,082 ms 显示，随后 4,096 → 8,192 字节为 62 ms，8,192 → 4,095 字节为 59 ms，再次写小到 1,536 字节为 1,070 ms。这一行为只依赖上次已确认的大小。

详细进程拆分、重复样本、原始时间和复跑命令见本机 `delivery-root/artifacts/cardinal-issue-4/r6-validation/bench/CPU与延迟实测.md`。日常全盘平均占用、大容量实体卷及其他 Mac 的表现待实机验收，Issue 继续开放。
