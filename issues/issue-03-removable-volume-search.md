# #3 HFS+ 与移动卷离线搜索

r5（0.1.27）已在本机打包，映像验收通过。Issue 保持开放，等待实体移动硬盘实测。[总管 #1](issue-01-overall-management.md) · [GitHub Issue #3](https://github.com/othercat/cardinal/issues/3)

## 实现与交付

- r5 在 r4 的 `0460a4d3c7564b8130ee8ba33e0fe7875f6912e0` 上开发和测试。该仓库使用 `master` 集成。
- HFS+、HFSX 优先使用 Darwin 的 `searchfs` 从卷目录批量读取名称、父目录、类型、大小与日期。检查目录关系和可见子项数量；快速读取不完整时，回退到原有的目录枚举。APFS 和其他可识别的本地外置卷使用目录枚举。
- 系统挂载、卸载和卷改名通知驱动「搜索卷」列表。卷缓存独立保存在 Mac 上，稳定 UUID 可复用，无法唯一确定身份的挂载有独立快照。在离线状态仍可用已保存的元数据查询、全局排序和翻页。重新连接时核对卷身份，回放有效的 FSEvents 日志，历史不可用时后台核对。r4 原有的本机快照继续使用格式 6。
- r5 交付时的包名为 `cardinal-release-r5-20261115.zip`，SHA-256 为 `30802b7744f5bb28a1b6ba28c1db320999e411e4f7a936ac2485a17591d01cc5`。解包后核对签名、arm64、最低 macOS 15.0、可执行权限、清单哈希和系统动态库依赖。296 个构建输入摘要见下方证据目录。产品为 ad-hoc 签名。

## 2026-11-15 验证

| 范围 | 操作与结果 |
| --- | --- |
| HFS+ 首次枚举 | M1 Pro、macOS 15.7.7，本机 SSD 上 16,664 项。枚举与组树逐项核对名称、父子关系、类型、大小和日期。每次重新挂载只读映像，两种方法交替各跑 5 次；卷目录读取中位数 39.164 ms，原目录遍历 792.642 ms。刚写完样本时单次热测分别为 55.102 ms 和 13.591 ms。计时未含挂载、保存或界面绘制。 |
| HFS+ 变体与权限 | 可写、只读、中文名、文件硬链接、符号链接、不可读子目录和 HFSX 的同目录大小写异名均与目录遍历结果一致。 |
| 插拔与身份 | 先后挂载同名 HFS+、APFS 映像，验证可见文件、实时创建/移动/删除、大小升降序、弹出后退出并恢复离线缓存、同名卷隔离、改挂载点及离线期间新增的文件。APFS Data 卷还单独验证了从已保存的设备游标回放并继续收到实时写入。 |
| 真实窗口 | 在隔离 bundle ID、测试监视目录的 WKWebView 中勾选挂载的 HFS+ 卷，按大小双向排序，改名后看到新行，弹出后仍显示离线行。正常退出，重新启动，验证勾选项和结果恢复，可按修改时间排序。取消勾选后回到本机测试文件。测试窗口放行了权限界面，操作系统权限未调整。 |
| 大结果集 | 30,000 条合成离线索引，对大小、创建时间和修改时间分别验证升降序，在首、中、末页逐项核对数值。 |
| 构建回归 | 根 workspace 的 `cargo check`、`cargo test`（1,819 项通过）、Clippy 均通过；Tauri 的 47 项默认测试、单独启用的磁盘映像集成测试及 Clippy 均通过。前端 typecheck、304 项 Vitest 测试及 Vite 生产构建通过。 |

本机留存原始测量、窗口回执、构建输入和解包校验，目录为 `delivery-root/artifacts/cardinal-issue-3/r5-validation/`。复核 HFS+ 目录与现有遍历的命令、样本和口径见其中的 `hfs-probe/README.md`。磁盘映像插拔测试入口为 `volumes::tests::mounted_disk_images_search_updates_and_offline_restart`，需将 `CARDINAL_VOLUME_TEST_DIR` 指向独立测试目录，并使用 `--ignored`。

实体 USB 或雷电硬盘尚待验证，重点是首次接入至结果可查的总时间、跨机写入后的同步，以及大规模离线搜索与排序。尚无数 TB 物理介质的用时数据。
